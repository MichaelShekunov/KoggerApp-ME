# Разъёмы Recorder на странице прибора

Состояние на 2026-10-24: **этап 1, только чтение**. Ветка `recorder-ports`. Контракт — спецификация форка
recorder `docs/Port-Config-Spec.md` (ветка `feat/port-config`), её пишет сессия «Logger Recorder GitLab».
Прошивка этапа 1 залита в прибор той сессией и проверена ею через kptools.

## Что видит пользователь

На странице Recorder под блоком «Recorder» есть блок «Разъёмы». В нём две группы: «Порты устройств» (разъёмы с
функцией) и «Универсальные разъёмы». На каждый разъём — карточка:

* подпись с платы: SONAR1, SONAR2, TELEM, GNSS, I2C, IN1,2, IN3,4, OUTS;
* функция, UART и скорость, например «Порт сонара A · USART2 · 57600 бод». Скорость портов сонара и GNSS меняется,
  пока они ищут скорость устройства;
* питание: «Батарея (VBAT), до ~30 В», «+5,2 В» или «Нет»;
* контакты: подпись (TX, RX, SCL, IN3, O1…), роль с живым значением, например «ШИМ на OUT1 · 1500 мкс», вывод МК и
  таймер. Если сохранённая роль отличается от действующей — «после перезагрузки: …».

В панели сервы строки OUT1…OUT3 называют контакты, на которые выводится каждый выход, например
«OUT1: IN1, IN3, O1». Пока таблица не прочитана, остаются прежние подписи.

## Протокол

* ID_BUS 0x17 GETTING v0 [шина] → описание шины.
* ID_PIN 0x16 GETTING v0 [контакт] → описание контакта.
* ID_PIN GETTING v1 без нагрузки → роли и значения всех контактов одним кадром.

Раскладки — в спецификации и в комментарии к `IDBinBus` (`src/id_binnary.h`).

* **Спрашивается только Recorder**, один раз за соединение и после перезапуска прибора. Никогда широковещательно:
  в кольце GODIO широковещательный GET стоит ведомой плате пинга.
* **Таблица читается по одному кадру:** шина 0, остальные шины, затем каждый перечисленный контакт. Следующий
  запрос уходит только после ответа.
* RespErrorID или 2 с тишины — у прошивки таблицы нет, блок скрыт.
* **Живые значения:** ID_PIN v1 раз в 200 мс, только пока блок раскрыт на видимой странице
  (`DevDriver::setPortsLive`).

## Проверки

* `tools/ports_check/run.ps1 -Mutants` — кадры байт в байт по значениям, которые сессия Recorder прочитала на
  приборе. **[проверено]** PASS, 8 из 8 мутантов.
* `tools/ports_check/ports_live.ps1 [-Shot файл.png]` — приложение против UDP-стенда с той же таблицей.
  **[проверено]** PASS:
  * каждая шина и каждый контакт запрошены по разу;
  * до открытия страницы v1 не шлётся, при открытой — ~5 раз в секунду;
  * 8 карточек, текст не обрезан, снимок просмотрен;
  * строка OUT1 панели сервы — «IN1, IN3, O1»;
  * ошибок QML нет.
* `tools/ports_check/ports_device.ps1 -Port COM17` — настоящий Recorder, только чтение. **[проверено 2026-10-24]**
  таблица прочитана верно:
  * 8 шин с подписями, питанием, функциями и UART;
  * 17 контактов, IN1/IN3/O1 — ШИМ на OUT1, остальные универсальные выключены, контакты портов — UART.

  Блок на странице и живой опрос этой проверкой не подтверждены: шаг открытия страницы искал прибор по адресу 0, а
  Recorder отвечает с 250 (исправлено, шаг `devicePage` с `"recorder": true`). Кроме того, COM17 держал запущенный
  KoggerApp владельца. Повторить, когда порт свободен.
