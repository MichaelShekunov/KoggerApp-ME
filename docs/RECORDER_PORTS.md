# Разъёмы Recorder на странице прибора

Состояние на 2026-10-24: **этап 1, только чтение**. Ветки `recorder-ports` (чтение таблицы) и `recorder-board`
(вид «плата»). Контракт — спецификация форка recorder `docs/Port-Config-Spec.md` (ветка `feat/port-config`), её пишет
сессия «Logger Recorder GitLab». Прошивка этапа 1 залита в прибор той сессией и проверена ею через kptools.

## Что видит пользователь

На странице Recorder под блоком «Recorder» есть блок «Разъёмы». В нём **плата сверху**: каждый разъём нарисован на
своём месте, рядом с ним — его блок.

* **Блок разъёма** (с 2026-10-27, по просьбе владельца «шрифт крупнее, лишнюю информацию убери»): подпись с платы
  жирным; у UART-разъёма — одна строка «функция … скорость сейчас» («сонар A … 57600»); у универсального — только
  контакты, которые что-то делают, в физическом порядке («IN3 … OUT1 · 1500 мкс»). Контакты GND и питания, TX/RX и
  выключенные контакты на схеме не показываются; они есть в меню разъёма. Шрифт — 18 единиц схемы (около 14 px на
  панели 540 px, было около 10), боковые блоки шире: 220 единиц.
  Рамка у портов устройств синяя, у универсальных разъёмов — оранжевая.
* **Питание** внизу: «POWER 5–30 V». Строки «+BAT 11,98 В · GND» и «рельс 5 В» (каналы 0 и 1 ID_VOLTAGE) появляются,
  только когда прибор их шлёт. Прошивка Recorder их пока не шлёт.
* **Нажатие на разъём** открывает под платой его меню:
  * питание разъёма;
  * функция;
  * «после перезагрузки», если сохранённое отличается от действующего;
  * предупреждение, если GNSS или телеметрия стоят на разъёме с VBAT.
* **Меню по функции.** Строки с меткой «резерв» ждут прошивку. Их раскладки уже записаны в спецификации (коммит
  882c0c7, ID_BUS V2–V5, ID_PIN V2–V5):
  * порт сонара (V2, V5, ID_DEV_SYNC): связь, скорость, UART; резерв — протокол, синхронизация пинга, запись в журнал,
    передача на хост, трафик и ошибки;
  * телеметрия (V3, V5): скорость, UART; резерв — что идёт на хост, загрузка канала;
  * навигация (V4, V5): связь, скорость, UART, строка «PPS: через универсальный вход» (на разъёме GNSS линии PPS нет);
    резерв — протокол, частота, фикс и спутники.
* **Универсальный разъём:** список контактов с выводом МК и ролью. Нажатие на контакт открывает меню роли:
  * ШИМ: какой OUTn, что им управляет (серва вручную, скан, стоит), импульс сейчас, таймер, кнопка «Открыть панель
    сервы»;
  * АЦП: напряжение сейчас; резерв — имя, делитель и масштаб, единицы, порог тревоги, запись в журнал;
  * вход: уровень, подтяжка; резерв — событие, антидребезг, счётчик импульсов, отметка в журнале, «как PPS или запуск
    пинга»;
  * выход: уровень; резерв — режим, длина импульса, «переключить, импульс сейчас».

**Место и порядок контактов** берутся из встроенной таблицы `knownLayout` в `qml/app/RecorderBoardView.qml`. Это
таблица ID_BUS V1 из спецификации для RECORDER Mini v4.0; по словам сессии Recorder, контакты сверены с PcbDoc.
Правила таблицы:

* места считаются по часовой стрелке;
* контакт 1 — первый по часовой;
* на левой стороне блок поэтому читается снизу вверх;
* у OUTS физический порядок O3, O2, GND, O1, не как в подписи.

Прибор V1 пока не отдаёт (в спецификации зарезервировано, в план не поставлено). Разъём, которого нет в таблице, встаёт
на свободное место.

В панели сервы строки OUT1…OUT3 называют контакты, на которые выводится каждый выход, например
«OUT1: IN1, IN3, O1». Пока таблица не прочитана, остаются прежние подписи.

## Протокол

* ID_BUS 0x17 GETTING v0 [шина] → описание шины.
* ID_PIN 0x16 GETTING v0 [контакт] → описание контакта.
* ID_PIN GETTING v1 без нагрузки → роли и значения всех контактов одним кадром.

Раскладки — в спецификации и в комментарии к `IDBinBus` (`src/id_binnary.h`).

* **Спрашивается только Recorder**, один раз за соединение и после перезапуска прибора. Никогда широковещательно:
  в кольце GODIO широковещательный GET стоит ведомой плате пинга.
* **Таблица читается по одному кадру:** шина 0, остальные шины, затем каждый перечисленный контакт. Следующий
  запрос уходит только после ответа.
* RespErrorID или 2 с тишины — у прошивки таблицы нет, блок скрыт.
* **Живые значения:** ID_PIN v1 раз в 200 мс, только пока блок раскрыт на видимой странице
  (`DevDriver::setPortsLive`).
* **Питание на схеме:** ID_VOLTAGE 0x31, канал 0 — VBAT, канал 1 — рельс +5,2 В. Приложение его не спрашивает, а
  принимает, когда прибор шлёт сам (`voltage0Mv`, `voltage1Mv`). Прошивка Recorder сейчас 0x31 не шлёт совсем: кадр
  только объявлен, модуль АЦП в сборку не входит (сессия Recorder, по исходникам). План — этап 4: CONTENT V0, U1
  канал, S4 мВ, раз в секунду, с адреса 250. Спецификация исправлена в коммите 28ddbe1.

## Функции и скорости UART-разъёмов (ID_BUS V0 SETTING, V2–V4)

Состояние на 2026-10-27: **сделано в приложении, не закоммичено**. Прошивочную часть сделала сессия «Проверка папки
GitLab» и, с её слов, проверила на приборе по USB (COM5). Контракт — `docs/Port-Config-Spec.md` форка recorder,
разделы ID_BUS V0 SETTING и V2–V4. Этот раздел заменил вчерашний выбор скорости только у TELEM: V3 теперь — настройка
функции «телеметрия» с «Авто», а не скорость разъёма.

**Что видит пользователь.** В меню каждого из четырёх UART-разъёмов (SONAR1, SONAR2, TELEM, GNSS) — строки:
* «Функция» — список: Сонар A, Сонар B, Телеметрия, Навигация. Выбор меняет функции местами: выбранная функция встаёт
  на этот разъём, а функция, которая стояла здесь, уходит на разъём, где выбранная была раньше. Каждая из четырёх
  функций всегда стоит ровно на одном разъёме.
* «Скорость» — «Авто» и 9600 … 5 000 000. Это скорость функции: при смене разъёма она переезжает вместе с функцией.
* «Скорость сейчас» — скорость разъёма из ID_BUS V0. При «Авто» она меняется, пока порт ищет скорость; пока открыта
  страница, приложение раз в секунду перечитывает по одному UART-разъёму.
* Пояснение: итог последней смены на этом разъёме или подсказка. Для телеметрии своё пояснение: на фиксированной
  скорости мост Wi‑Fi должен работать на той же; на «Авто» порт перебирает скорости после 3 с без запросов хоста.

Заголовок блока на схеме, меню разъёма и его раздел (сонар, телеметрия, навигация) берутся из функции, которую прибор
сообщает в V0. Ничего не задано заранее, после смены всё перестраивается. Предупреждение о VBAT на разъёме с
телеметрией или навигацией осталось.

Если связь с прибором не через последовательный порт (UDP или TCP, то есть через мост Wi‑Fi), списки видны, но
выключены, с пояснением. Последовательный адаптер на UART-разъёме приложение от USB не отличит. Его выдаёт ответ
прибора RespErrorRuntime (8): тогда на разъёме показывается «отказ: только через USB».

**Протокол** (`IDBinBus`, `DevDriver::setPortFunction`, `setPortBaud`):
* После таблицы портов настройки функций читаются по одной, следующая — только после ответа: GETTING v2 [1],
  v2 [2], v3 [3], v4 [4]. Какие функции читать, берётся из function caps.
* Ответ на чтение — CONTENT, затем RespOk. Шаг завершает CONTENT, RespOk пропускается.
* Любой другой код или 2 с тишины — у прошивки этой функции нет.
* Если не ответила ни одна функция, списки не показываются.
* Смена функции: SETTING v0 [разъём][функция][свой UART разъёма], затем на RespOk ID_FLASH v0 с ключом, затем на его
  RespOk четыре UART-разъёма перечитываются через V0. «Сохранено» — если на разъёме теперь выбранная функция.
* Смена скорости: SETTING v2/v3/v4 со скоростью. Остальные поля уходят такими, какими прибор их прислал; если не
  прислал — значения по умолчанию из спецификации. Затем ID_FLASH, затем GETTING той же версии и V0 разъёма, на
  котором стоит функция.
* Коды на SETTING: 1 — дальше; 8 — «только через USB»; 3 и любой другой — «настройка не принимается».
* Скорость не из списка не отправляется.
* В журнале строки начинаются с `ports:`.

**Проверки:**
* `tools/ports_check/run.ps1 -Mutants` — кадры V0 SETTING и V2–V4 байт в байт, разбор по функции, отказы, значения по
  умолчанию. **[проверено 2026-10-27]** PASS, поймано 16 мутантов из 16.
* `tools/ports_check/ports_live.ps1` — приложение против UDP-стенда, который играет прошивку с настройками.

  (115200), Сонар B на TELEM (115200), Навигация на GNSS (авто). **[проверено 2026-10-27]** PASS:
  * кадры в нужном порядке:

    * телеметрия 921600: v3, ID_FLASH, перечитаны настройки и её разъём;

* На приборе — **не проверено** приложением.
