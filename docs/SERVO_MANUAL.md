# Ручной режим сервы Recorder

Состояние на 2026-10-23. Сделано в ветке `servo-manual` по просьбе владельца, переданной сессией
«Logger Recorder GitLab». Прошивка Recorder с ручным режимом (`kogger/forks/recorder`, ветка
`feat/servo-pwm-x7`) залита в прибор. **С этим приложением проверено на приборе 2026-10-24** (раздел «Проверки»).

## Что видит пользователь

Панель сервы (Recorder на линии, например «On link COM17 · 921600»), блок Control:

* **Manual** — переключатель ручного режима. Серва встаёт на центр скана (в пределах хода серво) и держит
  угол. Скан ждёт: поля Scan и переключатель Enabled недоступны, у блока Scan подпись «Ждёт, пока серво в
  ручном режиме».
* **Крутилка** — угол задаётся перетаскиванием. Ручка поворачивается на столько же, на сколько указатель
  мыши повернулся вокруг центра, поэтому нажатие не дёргает серву в точку под курсором. С Shift — в 10 раз
  мельче. Колесо даёт шаг 1°, с Ctrl — 0.1°. Закрашенная дуга показывает ход серво: ±(Servo angle range)/2.
* **Поле «Угол, °»** рядом с крутилкой — точное значение с шагом 0.01°.
* **Current angle** в ручном режиме показывает заданный угол: Recorder в ручном режиме не шлёт ID_ATTITUDE.
* Если прошивка ручного режима не знает, переключатель возвращается в «выкл», а под ним появляется
  «Прошивка не поддерживает ручной режим». Признак держится до переподключения.

## Протокол

Новой команды нет. ID_SERVO_CONTROL = 0x27, версия 0, SETTING, 16 байт little-endian:

| поле | тип | |
|---|---|---|
| general | U2 | бит 0 — скан (Enable), **бит 1 — ручной режим (Manual)** |
| options | U2 | бит 0 — Reverse |
| pwm_min_us, pwm_max_us | U2, U2 | калибровка |
| angle_range_deg | S2 ×100 | ход серво |
| step_deg | S2 ×100 | шаг скана, ≠ 0 |
| range_deg | S2 ×100 | диапазон скана, ≥ 0 |
| center_deg | S2 ×100 | центр скана; **при Manual = 1 — угол, который держать** |

* Каждый SETTING с Manual = 1 сразу ставит серву в center_deg. Прошивка сама ограничивает угол
  ±angle_range/2 и [pwm_min, pwm_max] и применяет Reverse. Приложение тоже обрезает угол до ±angle_range/2.
* Остальные поля уходят текущими значениями.
* **Вход в ручной режим:** Manual = 1, center_deg — центр скана, обрезанный до хода серво.
* **Выход:** Manual = 0, center_deg — центр скана. Поэтому приложение хранит центр скана отдельно, пока
  center_deg занят ручным углом. Правка центра в это время запоминается и уходит при выходе. Если Enable = 1,
  скан стартует как при включении — с нижнего края диапазона (так делает прошивка).
* **Старая прошивка** отвечает на бит 1 RespErrorPayload. Если такой ответ пришёл, а ручной режим ещё ни разу
  не подтверждался, приложение снимает Manual у себя и ничего не шлёт: прибор из скана не выходил.

## Что известно о прошивке Recorder (ответ сессии «Logger Recorder GitLab», 2026-10-23)

* Recorder подтверждает кадр, только если в нём стоит флаг запроса ответа. Приложение ставит его на всё,
  кроме CONTENT (`proto_binnary.h`, `create`: `setMode(type, ver, type != CONTENT)`) **[проверено по исходнику]**.
  Ответ: тот же ID, CONTENT, та же версия, флаг ответа; 3 байта — код и два байта контрольной суммы принятого
  кадра. Новая прошивка на bit1 отвечает 1, старая — 3 (RespErrorPayload).
* На приборе, по словам той сессии: GETTING после SETTING с Manual возвращает general = 2 и center_deg,
  равный заданному углу (0, ±45, ±90°, шесть из шести) — через Kptools, не через это приложение.
* ~32 SETTING в секунду для прошивки — оценка по коду, не замер.
* Логический OUT1 в новой прошивке выводит один импульс на три контакта (по шелкографии): O1 (разъём
  «O1 O2 O3 GND», PA6, без питания), IN3 («IN3 IN4 GND 5V», PA0, TIM2_CH1), IN1 («IN1 IN2 GND 5V», PB0,
  TIM1_CH2N; собран, не залит). Подпись «OUT1 (wired)» не менялась: по версии (1.4) старую прошивку от
  новой не отличить.

## Темп и подтверждения

* Перетаскивание: первый кадр уходит сразу, дальше не чаще раза в 25 мс (40 кадров в секунду, PWM — 50 Гц).
  Значения между слотами не копятся: уходит последнее. При отпускании финальное значение уходит сразу.
  На Windows грубый таймер Qt растягивает слот до ~31 мс: замер — ~32 кадра в секунду, не больше 4 за 100 мс
  (`servo_live.ps1`, ниже). Это в пределах просьбы «не чаще 30–50 в секунду».
* Кадры ручного режима (вход, выход, угол) идут **без механизма подтверждения** (`hashBinFrameOut`). Он
  сверяет ответ с контрольной суммой последнего отправленного кадра. При 40 кадрах в секунду ответ всегда
  «не от того» кадра. Через 1.5 с класс решил бы, что управление сервой потеряно, и панель убрала бы прибор
  до следующего чтения.
* Вместо этого через 250 мс после входа, выхода или финального угла приложение читает состояние обратно
  (GETTING). Ответ с битом 1 подтверждает, что ручной режим поддерживается. В ответе center_deg — ручной угол.
* Остальные настройки (Reverse, калибровка) идут как раньше, с подтверждением. В ручном режиме они несут
  бит 1 и ручной угол.

## Код

* `src/id_binnary.*` — `IDBinServoControl`: `setManual`, `setManualDeg`, `dropManual`, `scanCenterDeg`.
* `src/device/dev_driver.*` — `servoManual`, `servoManualMove` (с темпом), `servoManualSet`,
  `servoManualSupport`, обратное чтение.
* `src/device/dev_q_property.h` — свойства для QML. Заодно `degToS2` округляет, а не отбрасывает дробь:
  4.1° раньше уходили как 4.09° (4.1 × 100 = 409.99999999999994 в double, отброшено до 409).
* `qml/app/ServoAngleDial.qml` — крутилка; `qml/app/ServoPanelBody.qml` — панель.

## Проверки

Все — 2026-10-23, без железа.

* `tools/servo_check/run.ps1 [-Mutants]` — офлайн: кадры байт в байт, обрезка угла, центр скана на входе и
  выходе, то, что кадры ручного режима не объявляют управление потерянным, а остальные настройки — объявляют,
  если ответа нет. **[проверено]** PASS, 10 из 10 мутантов пойманы.
* `tools/qml_check/servomanual_check.ps1 [-Shot файл.png]` — офлайн, настоящие `ServoPanelBody` и
  `ServoAngleDial` против выдуманного прибора: переключатель, блокировка скана, перетаскивание (без прыжка
  при нажатии, обрезка по краю, обратный ход сразу, Shift), колесо и Ctrl, поле, старая прошивка.
  **[проверено]** 9 из 9; снимок панели просмотрен.
* `tools/servo_check/servo_live.ps1 -Exe <сборка>` — приложение на скрытом рабочем столе против UDP-стенда,
  который играет Recorder по контракту. Два прогона:
  * с ручным режимом — вход с центром скана, обратное чтение, темп, финал, выход, управление ни разу не
    объявлено потерянным;
  * старая прошивка — отказ распознан, кадров с битом 1 больше нет.

  **[проверено]** PASS: 34 кадра на 181 вызов, не больше 4 за 100 мс, медиана 31.6 мс.
* `tools/servo_check/servo_device.ps1 -Exe <сборка> -Port COM17` — **настоящий Recorder**, серва
  поворачивается. Только по слову владельца. **[проверено 2026-10-24, слово владельца «3. да»]** PASS:
  * прибор по обратному чтению сообщил ручной режим и углы 0 → 45 → −45 → 30 → 0;
  * выход вернул скан с центром 0.00;
  * 55 кадров ручного режима, 61 подтверждение RespOk на настройки — подтверждены все;
  * перетаскивание: 272 вызова за 1.5 с, ~49 кадров (~32 в секунду), каждый с ответом.

  Это состояние, которое сообщил прибор. Само движение сервы этой проверкой не видно.

  sent N, settings answered K». Пишется после первого использования ручного режима на соединении.
