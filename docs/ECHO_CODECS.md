# Кодеки эхограммы

Состояние на 2026-10-24. Задача владельца, переданная сессией «GitLab (fork) COMPRESSION»: приложение понимает
все три кодека эхограммы. Владелец разрешил держать код echocodec в KoggerApp ME. Этот код из закрытого
репозитория, поэтому в публичный KoggerApp он не переносится.

| Кодек | Кадр | Кто шлёт | Где в приложении |
|---|---|---|---|
| KEC прежний | `ID_CHART_Z` 0x7D | GODIO до 2026-10-24, nanoSSS, Байкал | `src/kec`, `IDBinChartZ` |
| KEC с блоками целей | `ID_CHART_Z` 0x7D, бит 15 заголовка кадра KEC | GODIO с 2026-10-24 | тот же декодер |
| echocodec | `ID_CHART` 0x03 версии V3 | SonarN, режимы UNIFORM / PROGRESSIVE | `src/codec`, `IDBinChart` |

## KEC

`src/kec/kec.c`, `kec.h`, `kec_tab.h` — копия байт в байт из репозитория KoggerEchoCodec. Его HEAD — d9ac0e0,
сами исходники кодека последний раз менялись в fe8f505. Один декодер читает оба потока.
* Кадр без бита 15 кодирован как раньше.
* Бит 15 первого u16 заголовка кадра KEC значит, что в кадре есть флаги целей. Длина кадра — биты 0..14.
* Формат описан в `docs/FORMAT.md` того репозитория.

Приложение только раскодирует (`kec_decode_ping`). Кодировщик лежит рядом, чтобы файл не отличался от того, что
работает в приборе. Состояние кодировщика `kec_rc_state` теперь массив из 24 байт; приложение его не использует.

## echocodec (ID_CHART V3)

`src/codec/chart_codec.h` — копия из закрытого GitLab kogger/research/echocodec @ e6a02dd.
* Заголовок на C из функций `static inline`. Его один раз собирает C-обёртка `chart_codec_host.c`; C++ видит
  только `chart_codec_host.h`.
* Декодер считает во float. Обёртка собирается с `-ffp-contract=off`, иначе на Android arm64 компилятор
  сливает умножение со сложением, и отдельные ячейки расходятся с эталоном на единицу.

Кадр — один независимо раскодируемый блок пинга:
`[mode U1][resol_mm U1][count U2][seq U1][blk U1][поток блока]`, не длиннее 115 байт.
* mode 0 — равномерный, 1 — прогрессивный.
* Блок `blk` — ячейки `[blk·252, min(n, blk·252+252))` сжатой эхограммы длины `n`.

`ChartV3Assembler` (`src/codec/chart_v3.*`) собирает пинг:
* блоки одного пинга (одинаковые mode, resol, count, seq) приходят в любом порядке;
* пинг публикуется, когда пришли все блоки или когда пришёл кадр другого пинга;
* недостающий блок берётся из предыдущего опубликованного пинга, если у того та же геометрия (так задумано в
  SonarN), иначе остаётся нулём;
* запоздавший блок уже опубликованного пинга отбрасывается и текущий пинг не прерывает;
* блок за концом пинга, кадр короче заголовка и неизвестный режим отвергаются.

Опубликованный пинг лежит на родной сетке: count ячеек по resol_mm от дальности 0, как несжатый.
* В прогрессивном режиме полосы 10/15/20/30 мм начинаются на границах лестницы кодека (3, 6, 12 м), а не на
  накопленной сумме count × resol. Каждая родная ячейка берёт отсчёт той полосы, куда попадает её середина.
* Дальше пинг идёт через `IDBinChart::acceptDecoded`, тем же путём, что CHART_Z. Остальное приложение
  сжатия не видит.
* Если один кадр закрывает два пинга (короткий с пропусками и следующий целый из одного блока), второй
  заменяет первый раньше, чем его прочитают. Это бывает только у пингов короче 252 ячеек.

## Что видно в журнале

Раз в минуту, пока идут кадры эхограммы, для каждого прибора пишется:
`[адрес] echogram: N pings in S s; ID_CHART_Z D dropped for a missing slice, U the decoder refused;
ID_CHART V3 P pings, B blocks from the previous ping`.
* U > 0 — поток, которого декодер не знает. Так выглядел новый KEC до обновления `src/kec`.
* D > 0 и B > 0 — потери на линии.

## Проверки

* `tools/codec_check/run.ps1 [-Mutants]` — без Qt и без прибора, по тестовым наборам репозитория кодека
  (`KoggerEchoCodec/test/app_vectors`: 60 реальных пингов, сжатых каждым кодеком, и ожидаемые отсчёты).
  **[проверено]** 10 из 10, 6 из 6 мутантов:
  * `kec_v1.vec` и `kec_v2.vec` — по 60 пингов, 0 расхождений;
  * `echocodec_v3.vec` — 60 пингов (30 равномерных, 30 прогрессивных), блоки в обратном порядке, 0 расхождений;
  * родная сетка; начала полос на границах лестницы (шаг 11 мм); подстановка блока из предыдущего пинга;
    запоздалый блок; битые кадры.
* `tools/chartz_check/run.ps1` — классы приложения. **[проверено]** Всё прошло:
  * запись nanoSSS с CHART_Z: 16 пингов совпали с несжатыми двойниками, rms ≤ 1,46;
  * кадры ID_CHART V3 тестового набора через `FrameParser` и `IDBinChart`: 60 из 60 пингов, равномерные — как
    эталон.
* Живая плата GODIO (COM18, 921600). **[проверено 2026-10-24]**:
  * в захвате 3 с у всех 50 пингов есть блоки целей;
  * приложение за 60,1 с собрало 1051 пинг; потерянных и отвергнутых 0.

Приборов с echocodec (SonarN) у меня нет: V3 проверен только на тестовом наборе.
